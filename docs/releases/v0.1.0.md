## 发布结论

EMI Harness v0.1.0 已具备最小但完整的受控研发闭环：权威任务状态和人工门禁先于 Agent 运行，Pi 只承担 Agent Runtime，受治理资源和精确工具按 RunManifest 注入，有副作用操作经过独立 Gateway 和账本，Executor 不能自行宣布通过，Verifier 使用新 Session 和 Agent 外检查，最终候选交付停在人工验收前并能导出可校验 Evidence Package。

仓库所有者已指示本阶段产出作为 V0.1。本记录据此确认版本命名和工程验收，不把该指示解释为对校准 Task 或未来真实 EMI 项目的业务验收，也不调用 `accept_delivery` 伪造该事实。

## 已知限制

- Faux Provider 只提供确定性无网络模型响应，不衡量真实模型的推理质量、成本或供应商故障行为。
- 本地 Node helper 和 check process 不具备容器或虚拟机级网络、资源和文件系统隔离，不能直接处理不可信生产仓库。
- V0.1 只有一个写工具、一条 safeguarding Context、一个 Skill 和一种 Node check，不代表完整 EMI 研发能力。
- 未接入真实 IAM、远程 Git/CI、审批系统、工单、长期 Evidence 存储、签名或时间戳服务。
- 未使用客户数据、生产凭据或真实 EMI 项目，因此 DORA、GDPR、AML/CFT、制裁和成员国实施要求均未获得业务层验证。

## 下一阶段

下一步不是自动扩大目录或工具集合，而是选取一个真实、低风险、边界清楚的 EMI 研发任务，由产品、架构、合规或法律责任人确认 PRD、司法辖区、适用 Context 和验收标准后运行 V0.1。发现的问题按 Task、Run、RoleRun、Operation 和 Evidence 引用形成校准记录，再共同决定 V0.2 的具体范围。
